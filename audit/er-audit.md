# Аудит ER-моделі (Lab 1)

Порівняння `model/er.mmd` (згенеровано AI, Prompt 3) зі `spec.md`.

## Знайдені розбіжності

| # | Що не так | spec | модель | Важливість |
|---|-----------|------|--------|------------|
| 1 | Атрибут `id` додано, хоча в переліку атрибутів spec його немає (порушення інструкції промпту) | `id` лише в критеріях | `int id PK` у кожній сутності | висока |
| 2 | Англійські назви сутностей не задані в spec — критерій «назви збігаються» неперевірний | лише українські назви | `CUSTOMER`, `STOCK`, ... | висока |
| 3 | Типи атрибутів обрав AI | типів немає | `decimal`, `datetime`, `string`, `int` | висока |
| 4 | Не зафіксовано, що на пару товар+точка — рівно один залишок | немає правила | можливі дублі `STOCK` | низька |
| 5 | `working_hours` одним рядком | тип не вказано | `string` | низька |
| 6 | Зовнішні ключі не показані | не вимагаються | лише лінії зв'язків | низька |

## Топ-3 виправлення

### Розбіжність #1 — атрибут `id` відсутній у spec
- **Що було:** AI додав `int id PK` у кожну сутність, хоча в переліку
  атрибутів spec `id` не було (порушення інструкції промпту
  «не додавай атрибутів, яких немає в spec»).
- **Пункт spec:** «Сутності та атрибути» + критерій «id всіх сутностей
  одного типу — integer».
- **Виправлення spec:** додала `id` в атрибути кожної сутності → коміт `13097d5`
- **Виправлення моделі:** модель не змінювалась — після оновлення spec
  вона відповідає йому.
- **Промпт:** `ai/ai-work-log.md` → Prompt 3, питання 2

### Розбіжність #2 — англійські назви сутностей відсутні у spec
- **Що було:** у spec сутності мали лише українські назви, тому AI сам
  обрав англійські (`CUSTOMER`, `STOCK` тощо). Критерій «назви
  збігаються» стосувався лише атрибутів, тож назви сутностей на схемі
  неможливо було перевірити проти spec.
- **Пункт spec:** «Сутності та атрибути» + критерій «назви атрибутів
  у spec і на схемі збігаються».
- **Виправлення spec:** додала англійські назви до кожної сутності та
  розширила критерій до «назви сутностей і атрибутів» → коміт `7a6c2ee`
- **Виправлення моделі:** модель не змінювалась — назви, обрані AI,
  залишила без змін; тепер вони зафіксовані у spec.
- **Промпт:** `ai/ai-work-log.md` → Prompt 3, питання 1

### Розбіжність #3 — типи атрибутів обрав AI
- **Що було:** у spec типи атрибутів не були вказані, тому AI сам
  обрав їх у моделі (`string`, `decimal`, `datetime`, `int`). Типи
  на схемі неможливо було перевірити проти spec.
- **Пункт spec:** «Сутності та атрибути» + «Критерії прийняття».
- **Виправлення spec:** додала критерій із типами атрибутів:
  `id` і кількості — integer, ціни — decimal, дати — datetime,
  решта — string → коміт `08fa669`
- **Виправлення моделі:** модель не змінювалась — після перевірки всі
  типи в `er.mmd` відповідають новому критерію.
- **Промпт:** `ai/ai-work-log.md` → Prompt 3, питання 3

## Решта (низька важливість)
- #4: правило «на пару товар + точка — рівно один залишок» у ER-діаграмі
  не відображається; фіксую як обмеження, якщо знадобиться в наступних
  лабах.
- #5: `working_hours` залишаю одним рядком (`string`) — для цієї моделі
  достатньо.
- #6: зовнішні ключі не додаю — завдання їх не вимагає, зв'язки
  показані лініями.
